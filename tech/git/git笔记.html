1、什么是GIT？ ​

Git是一个免费、开源的分布式版本控制软件,用以有效、高速的处理从很小到非常大的项目版本管理。

2、什么是版本控制？ ​

版本控制是一种记录一个或若干个文件内容变化，以便将来查阅特定版本修订情况的系统。

说到版本控制，脑海里总会浮现大学毕业是写毕业论文的场景，你电脑上的毕业论文一定出现过这番景象！

5. 区域划分 ​

我们先来理解下 Git 工作区、暂存区和版本库概念：

  • **工作区：**就是你在电脑里能看到的目录。该区域的文件会有状态的变化且状态由git自动检测，如果程序中文件做任何操作（增、删、改），文件状态均会被检测到，可以使用 【git status】命令查看。

  • **暂存区：**英文叫 stage 或 index。一般存放在 .git 目录下的 index 文件（.git/index）中，所以我们把暂存区有时也叫作索引（index）。

  • **版本库：**工作区有一个隐藏目录 .git，这个不算工作区，而是 Git 的版本库。

工作区：

​ 代码直接写在这里，每一行代码都在，你真实能看到的位置

​ 你书写的代码书写内容的真实位置

暂存区：

​ 暂时存放你要生成历史版本节点的文件，当你生成历史版本后就会消失

​ 暂时存储一些内容，存储的不是文件是节点，把你想要形成历史版本的节点的内容暂时存储一下

历史区：

​ 会把暂存区里面的所有内容都拿过来形成一个历史版本，永久保存

​ 已经形成的历史版本，将来可以‘’穿越‘’回来的历史节点，历史区只能把暂存区里面的内容形成历史版本节点，不能直接操作工作区

向远程仓库上传的时候：

​ git只能上传历史区的内容，不能上传暂存区和工作区的内容。如果你的历史区没有内容会告诉你没有内容上传

）

6. git 工作流程 ​

1.在工作目录中添加、修改文件；

2.将需要进行版本管理的文件放入暂存区域；

3.将暂存区域的文件提交到git本地仓库,形成历史版本;

4.将git 本地仓库的文件推送到远程仓库;

7. 分支操作 ​

branch称为分支

当你初始化仓库以后，会自动生成一个分支叫做 master即主分支，根分支；

我们可以开辟更多的分支，去分别书写内容，每一分支上的内容都是相对独立。

一般开发新功能流程为：开发新功能时会在分支dev上进行，开发完毕后再合并到master分支。

7.6 冲突问题 ​

  • 冲突场景

    如果分支A在1.txt中加入了文本'22222'

10. 三个git相关文件 ​

git占位文件 .gitkeep ​

当你使用git管理文件夹的时候，空文件夹不会被管理

当时在初始化项目的时候，先把目录结构准备好，上传一次，比如就会有img文件夹，但是没有图片

git给我们提供了一个这样的文件，叫做.gitkeep 没有名称只有后缀，在vscode里面创建

没有特殊的意义，就是为了在空文件夹的时候，进行占位，保持文件夹结构

git忽略文件 .gitignore ​

git忽略文件:在我们开发过程中，如果有一些文件并不希望被git所管理（比如node_modules文件夹）

可以新建一个.gitignore文件，在里面书写你不希望 git 帮你管理得文件或者文件夹

【这个文件没有名字，只有后缀，window下如果不能直接创建，可以通过vscode】

【文件的位置必须与.git文件同级】

我们可以把一些与项目无关的文件忽略，有以下几种写法

新建一个 .gitignore文件，然后在里面写相关的顾略规则

1 某个文件

js
文件名.后缀
目录名/文件名.后缀
1
2

2 某个文件夹下所有的文件

目录名/
1

3 忽略文件夹下某个格式的文件

目录/*.后缀
1

4 文件名包含某种写法的文件

内容*
1

想要让大家共享忽略内容的话，我们需要把.gitignore文件上传到git仓库

git说明文件 readme.md ​

说明文件:对当前仓库内容得描述和说明解释。按照markdown的书写规则书写

上传到远端仓库时（比如码云，github）。readme中的内容会按照md的格式显示在仓库的首页。

        => 初始化项目以后, 就会直接从 master 上开辟的分支
        => 不接受任何代码上传
        => 只接收 主功能分支 合并的内容
        => 存储再开发过程中的每一个阶段内容
      3. 主功能分支 - feature-xxx
        => 直接从 dev 分支上开辟出来的分支
        => 进行各个功能的开发
        => 开发完毕以后吧代码合并到 dev 分支上
        => 接收文件上传
      4. 功能 bug 解决分支 - feature-xxx-fix-xxx
        => 再项目运行过程中, 出现 bug 进行修复的分支
        => 都是从 功能分支 上开辟出来的
        => 修改完毕以后合并到 功能分支上
        => 再由功能分支合并到 dev 分支上
      5. 紧急 bug 解决 - hot-fix-xxx
        => 直接从 master 上开辟
        => 进行紧急的 bug 修复
        => 修复完毕以后, 直接合并到 master 上
